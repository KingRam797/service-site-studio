# Delivery Checklist

## Scope and authority

- [ ] One decision-maker approved the final scope.
- [ ] Services, prices, policies, capacity, and confirmation language are owner-approved.
- [ ] Every asset has permission and provenance.
- [ ] No invented review, credential, award, result, or claim appears.
- [ ] Out-of-scope requests are documented separately.

## Content and design

- [ ] The hero states one customer-facing promise and one primary action.
- [ ] Real proof appears before generic explanation.
- [ ] The typography, composition, palette, and signature device come from this business.
- [ ] The site cannot be mistaken for the previous client build.
- [ ] Contact details, social links, locations, hours, and pricing are accurate.
- [ ] Empty, loading, success, and failure states tell the visitor what to do.

## Customer path

- [ ] Every service points to a valid next action.
- [ ] Form fields match the selected operations module.
- [ ] Required dates, durations, buffers, caps, and lead times are enforced.
- [ ] Confirmation language distinguishes a request from a confirmed booking.
- [ ] Payment success, cancellation, webhook, duplicate-event, and retry paths are tested when applicable.
- [ ] Direct delivery and email/SMS fallback are tested.

## Mobile and access

- [ ] Tested at 320, 375, 768, 1024, and 1440 CSS pixels.
- [ ] Tested on at least one physical phone.
- [ ] Primary action stays reachable without covering required controls.
- [ ] Keyboard order, visible focus, labels, alt text, headings, and contrast are checked.
- [ ] Reduced-motion mode remains usable.

## Production

- [ ] Configuration validation passes.
- [ ] Unit tests pass.
- [ ] Lint passes.
- [ ] Production build passes.
- [ ] Environment variables are configured outside source control.
- [ ] Database migrations are repeatable when applicable.
- [ ] Metadata, favicon, social card, canonical URL, and structured data are verified.
- [ ] Analytics ownership and consent behavior are documented.
- [ ] Custom domain and HTTPS work.
- [ ] Production form/booking/payment is tested with the owner.
- [ ] Rollback or recovery path is documented.

## Owner handoff

- [ ] Owner has domain, hosting, booking/payment, email, database, and analytics access.
- [ ] Recurring costs and renewal dates are listed.
- [ ] The owner knows how leads arrive and how to confirm them.
- [ ] Maintenance boundary and response time are written.
- [ ] Repository, live URL, final approvals, and launch date are recorded.
